# 궁리 자동 수집기 (TourAPI → 궁리 앱)

한국관광공사 TourAPI에서 가볼 곳·행사 정보를 **하루 한 번** 받아 `feed/gungri_feed.json` 으로 저장합니다.
앱(관리자 → 콘텐츠 → 콘텐츠 검수 → **자동 수집** 카드)에서 이 파일을 불러오면:

- 새 장소·행사는 **QA 대기**로 들어옵니다. 회원에게는 보이지 않습니다.
- 이미 있는 장소·행사는 새로 만들지 않고 **비어 있는 칸만** 채웁니다. 관리자가 🔒 고친 칸은 건드리지 않습니다.
- 사진은 **공공누리 유형(Type1·Type3)이 표시된 것만** ‘사용권 확인 중’으로 들어옵니다. 대표가 확인하면 회원 상세에 사진과 출처가 표시됩니다.
- **공개는 지금처럼** 스텝 검수 → 대표 ‘저장하고 공개’로만 합니다.
- 좌표는 참고값으로만 보관하고 길찾기에 자동으로 쓰지 않습니다.

## 1. 준비물 (선생님이 하실 일)

| 준비물 | 방법 |
|---|---|
| **TourAPI 인증키** | 공공데이터포털(data.go.kr) 가입 → ‘한국관광공사_국문 관광정보 서비스_GW’ 검색 → **활용신청**(무료, 개발계정은 보통 바로 승인). 마이페이지 → 활용신청 현황에서 **일반 인증키(Decoding)** 를 복사합니다. |
| **GitHub 계정·저장소** | github.com 가입 → 새 저장소(예: `gungri-feed`) 만들기. 피드는 공개 자료라 **공개 저장소**를 권장합니다. 앱이 주소로 바로 읽을 수 있습니다. 인증키는 저장소에 올라가지 않습니다. |

## 2. 설치 (한 번만)

1. 이 폴더 전체(`collector/`, `.github/`, `feed/`, `README.md`)를 저장소에 올립니다. GitHub 웹에서 ‘Add file → Upload files’로 폴더째 끌어다 놓으면 됩니다.
2. 저장소 **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `TOURAPI_KEY`
   - Secret: 복사한 인증키
3. **Settings → Actions → General → Workflow permissions** 를 **Read and write permissions** 로 바꿉니다. 수집 결과를 저장소에 저장하려면 필요합니다.
4. **Actions** 탭 → ‘궁리 자동 수집 (TourAPI)’ → **Run workflow** 로 첫 실행을 합니다. 1~3분 뒤 `feed/gungri_feed.json` 이 생깁니다.
5. 그 뒤로는 **매일 05:10(한국시간)** 에 자동으로 실행됩니다.

## 3. 앱에 연결

1. 저장소에서 `feed/gungri_feed.json` 을 열고 **Raw** 버튼을 누른 뒤, 주소창 주소를 복사합니다.
   예: `https://raw.githubusercontent.com/아이디/gungri-feed/main/feed/gungri_feed.json`
2. 앱: 관리자(또는 스텝) → 콘텐츠 → 콘텐츠 검수 → **자동 수집** 카드 → 피드 주소에 붙여 넣고 **주소에서 불러오기**를 누릅니다.
   - 한 번 넣은 주소는 기억합니다. 앱을 열 때마다 새 피드를 자동으로 받아 반영합니다.
   - 인터넷이 안 될 때는 JSON 파일을 받아 **파일에서 불러오기**로 넣어도 됩니다.
3. 대표: 카드의 **공공누리 사진 n장 사용권 확인** → 각 항목 ‘정보 보기·수정’에서 내용 확인 → **저장하고 공개**.

## 4. 설정 바꾸기 (`collector/config.json`)

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `regions` | 받을 시·도(법정동 코드). 11 서울, 41 경기, 28 인천, 51 강원, 43 충북, 44 충남, 30 대전, 36 세종, 52 전북, 46 전남, 29 광주, 47 경북, 27 대구, 48 경남, 26 부산, 31 울산, 50 제주 | 전국 |
| `placeContentTypes` | 12 관광지, 14 문화시설, 38 쇼핑(시장), 28 레포츠 | 네 가지 |
| `maxDetailsPerRun` | 하루에 상세를 받을 최대 건수(1건당 호출 3번) | 200 |
| `dailyCallBudget` | 하루 호출 상한(개발계정 한도 1,000건보다 작게) | 900 |
| `festivalDaysAhead` | 오늘부터 며칠 뒤 시작하는 행사까지 받을지 | 60 |
| `excludeTitleKeywords` | 이 말이 들어간 이름은 받지 않음 | 키즈·클럽·숙박 등 |

처음 며칠은 전국 자료를 나눠서 받습니다(하루 200건). 그 뒤로는 **바뀐 것만** 받아서 호출이 크게 줄어듭니다.

## 5. 확인·문제 해결

- **인증키 확인**: 내 컴퓨터에서 `TOURAPI_KEY=키 python -m collector.run --probe`. 호출 5건 정도로 키와 응답 항목을 보여 줍니다.
- **키 없이 시험**: `python -m collector.run --mock --out feed_test` (예시 자료 5곳·행사 1건)
- **시험 코드**: `python -m unittest collector.test_collector`
- `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`: 활용신청 직후 키가 반영되기까지 몇 시간 걸릴 수 있습니다. Encoding·Decoding 키를 바꿔 넣어 보세요.
- Actions가 실패하면 Actions 탭의 실행 기록에서 ‘수집’ 단계 로그를 확인합니다.

## 6. 자료 원칙

- 출처는 항목마다 `sourceLabel`(한국관광공사 TourAPI · 공식 홈페이지)과 확인일(`checkedAt`)로 기록합니다.
- TourAPI는 운영시간·요금이 비어 있거나 오래된 경우가 있습니다. 앱 규칙대로 **확인일 180일 이내**일 때만 회원에게 운영시간·요금을 보여 줍니다.
- 행사는 종료일이 지나면 피드에서 빠지고, 앱에서는 자동으로 ‘종료’ 처리되며 이력은 남습니다.

## 7. 큐레이션 목록 (로컬100 등)

`collector/curation/` 폴더의 목록 파일(JSON)과 이름이 맞는 장소·행사에는 피드에 `"curation": ["로컬100"]` 표시가 붙습니다.
- 현재 들어 있는 목록: **로컬100**(문화체육관광부·지역문화진흥원, 2024.12 발간) 100건 — 명소 58 · 콘텐츠 40 · 명인 2
- 로컬100 축제는 해마다 날짜가 바뀝니다. 그래서 목록에 날짜를 넣지 않았고, TourAPI 행사로 실제 날짜가 들어올 때 표시만 붙입니다.
- 새 목록(예: 2세대 로컬100, 한국관광 100선)을 넣을 때는 같은 형식으로 파일을 하나 더 넣으면 됩니다: `{"name":"목록 이름","items":[{"id":"…","name":"…","kind":"PLACE|FESTIVAL"}]}`
